# Spec - 보이스피싱 통화 분석 MVP 프론트엔드

> 이 Spec은 비교표에서 체크된 요구사항을 기준으로 프론트엔드 구현 범위를 고정한다. `PRD_SDD.md`는 참고만 하며 수정하지 않는다.

## Why

- **페르소나**: 통화 후 녹음파일을 확인하고 보이스피싱 의심 여부를 알고 싶은 PC 사용자
- **상황**: 사용자가 한국어 통화 녹음파일을 업로드하고 분석 진행 상태와 결과를 확인한다.
- **문제**:
  1. 통화가 정상 절차인지 보이스피싱인지 사용자가 즉시 판단하기 어렵다.
  2. 분석이 진행 중인지 실패했는지 알기 어렵다.
  3. 결과를 법적 확정 판정으로 오해하지 않도록 참고 정보와 대응 안내를 함께 제공해야 한다.
- **측정 지표**: Mock API 기준 업로드부터 결과 표시까지의 E2E 흐름 동작 여부, 성공·실패·취소 상태 처리 여부, `pnpm lint` 및 `pnpm build` 통과 여부

## Goal

- **해결 목표**: PC 웹에서 통화파일을 업로드하고, 분석 진행 상태와 보이스피싱 의심 결과·위험 구간·대응 안내를 확인할 수 있게 한다.
- **성공 기준**:
  - 동의 전 업로드·분석 기능이 비활성화된다.
  - `WAV`, `MP3`, `M4A` 파일을 검증하고 분석 작업을 시작할 수 있다.
  - `job_id` 기반으로 queued부터 completed, failed, cancelled 상태를 표시한다.
  - 완료 결과에 라벨, 의심도 점수, 최대 3개 위험 구간, 요약·대응 안내를 표시한다.
  - Mock API를 실제 API와 구분하여 사용할 수 있다.
  - API Base URL을 환경변수로 교체할 수 있다.
  - 음성파일·전사문·분석 결과를 브라우저에 영구 저장하거나 로그에 출력하지 않는다.
- **Out of Scope**:
  - 전체 전사문 표시
  - 화자 표시
  - 위험 구간 음성 재생
  - TTS 또는 음성 경고
  - 분석 이력 저장
  - 결과 파일 다운로드
  - 모바일 앱 및 실시간 통화 분석
  - 자동 신고·보호자 연락
  - 설정값을 변경하는 사용자 설정 기능

## What

### Happy Path

1. 사용자가 업로드 페이지에 진입한다.
2. 개인정보 안내를 확인하고 동의한다.
3. 프론트엔드가 모델 준비 상태를 확인한다.
4. 모델이 준비되면 `WAV`, `MP3`, `M4A` 파일 선택을 활성화한다.
5. 파일 형식과 기본 입력 조건을 검증한다.
6. 사용자가 분석을 시작하면 `POST /analyze`를 호출하고 `job_id`를 보관한다.
7. 분석 진행 페이지에서 작업 상태와 단계·진행 정보를 표시한다.
8. 사용자가 취소하면 `DELETE /analyze/{job_id}`를 호출한다.
9. 작업이 완료되면 결과를 표시하고, 실패하면 오류와 재시도 방법을 표시한다.
10. 결과 페이지에서 라벨, 의심도, 최대 3개 위험 구간, 요약·대응 안내와 참고 판정 문구를 표시한다.

### Edge Cases

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 개인정보 동의 전 파일 선택 또는 분석 시도 | 파일 업로드와 분석 시작을 비활성화한다. |
| EC-02 | 지원하지 않는 확장자 | 파일을 거부하고 지원 형식을 안내한다. |
| EC-03 | 모델 준비 중 또는 준비 실패 | 업로드를 비활성화하고 상태·재확인 안내를 표시한다. |
| EC-04 | 분석 작업 생성 실패 | 오류 안내를 표시하고 재시도할 수 있게 한다. |
| EC-05 | 분석 진행 중 취소 | 취소 요청 후 cancelled 상태를 표시하고 결과를 표시하지 않는다. |
| EC-06 | 분석 실패 | 전문 스택 트레이스 대신 사용자용 오류 문구와 재시도 버튼을 표시한다. |
| EC-07 | 정상 통화 결과 | 위험 구간을 표시하지 않고 정상 통화 결과와 안내 문구를 표시한다. |
| EC-08 | 보이스피싱 의심 결과 | 위험 구간을 최대 3개만 표시하며 화자·음성 재생은 표시하지 않는다. |
| EC-09 | Mock API 사용 | 실제 백엔드로 요청하지 않고 Mock 어댑터를 사용한다. 화면에는 Mock 사용 상태를 식별 가능하게 표시할 수 있다. |
| EC-10 | 실제 API 전환 | `NUXT_PUBLIC_USE_MOCK=false`와 실제 `NUXT_PUBLIC_API_BASE`로 환경변수만 교체한다. |

## How

### 기술 및 배포 기준

- Nuxt 3
- Vue 3
- Tailwind CSS
- Pinia
- 프론트엔드 소스·설정·Mock API·환경파일은 저장소의 `frontend/` 폴더 안에서만 관리한다.
- 백엔드·모델·기존 프로젝트 폴더는 프론트엔드 구현을 위해 임의로 수정하지 않는다.
- 프론트엔드 Spec 문서만 예외적으로 `docs/specs/frontend.md`에 관리한다.
- 프론트엔드 배포: Netlify
- 백엔드: Railway FastAPI API를 환경변수로 연결
- 실제 API 주소와 Mock 사용 여부는 프론트 공개 환경변수로 관리한다.

```env
NUXT_PUBLIC_USE_MOCK=true
NUXT_PUBLIC_API_BASE=http://localhost:8000
```

실제 API 연결 시:

```env
NUXT_PUBLIC_USE_MOCK=false
NUXT_PUBLIC_API_BASE=https://<railway-api-host>
```

### API 계약

프론트엔드는 `useAnalysisApi()`를 통해 Mock 어댑터 또는 실제 HTTP 어댑터를 호출한다. 페이지 컴포넌트에서 직접 `fetch`하지 않는다.

| Method | Path | 용도 |
|---|---|---|
| GET | `/health` | API 서버 상태 확인 |
| GET | `/model-status` | 모델 준비 상태 확인 |
| POST | `/analyze` | `audio` 파일로 분석 작업 생성 |
| GET | `/analyze/{job_id}` | 분석 상태와 완료 결과 조회 |
| DELETE | `/analyze/{job_id}` | 분석 취소 및 결과 폐기 |

분석 생성 요청:

```text
Content-Type: multipart/form-data
Field: audio
```

작업 생성 응답:

```json
{
  "job_id": "job_12345",
  "status": "queued",
  "stage": "queued"
}
```

완료 결과의 프론트 공통 필드:

```json
{
  "job_id": "job_12345",
  "status": "completed",
  "stage": "completed",
  "result": {
    "label": "보이스피싱 의심",
    "score": 91.0,
    "summary": {
      "title": "보이스피싱 의심",
      "description": "참고용 결과 안내입니다."
    },
    "segments": [
      {
        "start_time": "01:24",
        "end_time": "01:36",
        "text": "확인이 필요한 대화 내용",
        "reason": "의심 근거"
      }
    ],
    "advice": ["공식 기관 대표번호로 확인하세요."]
  }
}
```

Mock API는 위 공통 계약을 기준으로 queued, preprocessing, transcribing, classifying, finalizing, completed, failed, cancelled 상태를 재현한다. 실제 백엔드 응답이 확정되면 `useAnalysisApi()`의 변환 계층만 조정한다.

### 데이터·보안 제약

- 음성파일, 전사문, 분석 결과를 `localStorage`, `sessionStorage`, IndexedDB 또는 영구 파일로 저장하지 않는다.
- 브라우저 콘솔과 애플리케이션 로그에 음성 내용, 전사문, 개인정보, 인증정보를 출력하지 않는다.
- `.env`는 커밋하지 않고 `.env.example`에는 실제 비밀값을 기록하지 않는다.
- 개인정보 안내 문구는 현재 임시로 “외부로 전송하지 않습니다”를 사용한다.
- 실제 운영 문구가 확정되면 화면 문구만 교체할 수 있도록 상수 또는 컴포넌트로 분리한다.

### 현재 미결정으로 표시할 항목

- 최대 파일 크기와 최대 음성 길이
- 숫자 진행률·예상 완료 시간의 실제 백엔드 제공 여부
- 5단계 위험도 점수 구간
- 위험 구간 `reason` 필드의 실제 API 제공 여부
- `start_time`, `end_time`의 최종 형식
- `summary` 필드와 `advice` 문구의 최종 백엔드 계약

위 항목은 Mock 화면 검증을 위해 임시 데이터로 표현할 수 있지만, 실제 API 계약으로 확정했다고 간주하지 않는다.

## AC (Given-When-Then)

**AC-01 · 동의 전 업로드 제한**

- GIVEN: 사용자가 개인정보 처리에 동의하지 않음
- WHEN: 파일 선택 또는 분석 시작을 시도함
- THEN: 업로드·분석을 진행하지 않고 동의 안내를 표시한다.

**AC-02 · 지원 파일 검증**

- GIVEN: 사용자가 파일을 선택함
- WHEN: 파일 확장자 또는 기본 형식을 확인함
- THEN: `WAV`, `MP3`, `M4A`만 허용하고 나머지는 사용자용 오류를 표시한다.

**AC-03 · Mock 분석 작업 생성**

- GIVEN: 동의가 완료되고 모델 상태가 준비됨
- WHEN: 사용자가 분석 시작을 누름
- THEN: Mock `POST /analyze`가 `job_id`, `queued`, `stage`를 반환하고 진행 페이지로 이동한다.

**AC-04 · 분석 상태 표시**

- GIVEN: 진행 페이지에 유효한 `job_id`가 있음
- WHEN: 상태 조회가 반복됨
- THEN: 분석 단계와 로딩 상태를 표시하고 `completed`, `failed`, `cancelled` 중 하나가 되면 조회를 중단한다.

**AC-05 · 분석 취소**

- GIVEN: 분석 작업이 완료되지 않음
- WHEN: 사용자가 취소 버튼을 누름
- THEN: `DELETE /analyze/{job_id}`를 호출하고 cancelled 상태 및 결과 폐기 안내를 표시한다.

**AC-06 · 완료 결과 표시**

- GIVEN: 분석 상태가 completed임
- WHEN: 결과 응답을 수신함
- THEN: 라벨, 의심도, 요약, 최대 3개 위험 구간, 대응 안내를 표시하며 화자·전체 전사문·음성 재생은 표시하지 않는다.

**AC-07 · 실패 및 재시도**

- GIVEN: 분석 상태가 failed임
- WHEN: 오류 응답을 수신함
- THEN: 스택 트레이스나 개인정보 없이 사용자용 오류와 재시도 동작을 표시한다.

**AC-08 · 실제 API 전환**

- GIVEN: 실제 Railway API 주소가 전달됨
- WHEN: `NUXT_PUBLIC_USE_MOCK=false`와 실제 Base URL을 설정함
- THEN: 페이지 코드를 수정하지 않고 실제 API 어댑터로 요청 대상을 전환할 수 있다.

**AC-09 · 개인정보 비저장**

- GIVEN: 분석이 성공·실패·취소 중 하나로 종료됨
- WHEN: 프론트엔드 상태가 정리됨
- THEN: 음성파일·전사문·분석 결과를 브라우저 영구 저장소에 남기지 않는다.
