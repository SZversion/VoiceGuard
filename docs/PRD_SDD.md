# Part 1. PRD

## 1. 제품 개요

보이스피싱 통화 녹음파일을 업로드하면 한국어 음성 전사와 텍스트 분류를 수행하여 통화가 정상인지 보이스피싱으로 의심되는지 안내하는 서비스입니다.

사용자는 최종 이진 분류 결과와 보이스피싱 의심도, 의심 결과일 때 모델 점수가 높은 대화 구간을 확인할 수 있습니다. 이 서비스는 법적·수사적 확정 판정이 아닌 참고 정보를 제공합니다.

### One-Line Definition

통화 녹음파일을 분석하여 보이스피싱 의심 여부와 확인이 필요한 대화 구간을 제공하는 PC용 음성 분석 서비스입니다.

## 2. 문제 정의

보이스피싱은 기관 사칭, 긴급성, 비밀 유지 요구, 개인정보·송금 요구를 정상적인 절차처럼 구성합니다. 사용자는 통화 당시 위험을 인지하지 못하거나 통화 종료 후에도 피해 상황을 판단하기 어려울 수 있습니다.

정상 금융 상담에도 계좌, 대출, 이체, 본인 확인 등의 표현이 사용되므로 특정 단어만으로 판단할 수 없습니다. 전체 통화의 문맥을 전사하고 분류하여 사용자가 다시 확인할 구간을 제공해야 합니다.

## 3. 목표 사용자

- 보이스피싱 통화를 정상적인 금융·수사 절차로 오인하기 쉬운 사용자
- 통화 후 녹음파일을 확인하고 싶은 PC 사용자
- 정상 금융 상담과 의심 통화를 구분하기 어려운 사용자

MVP는 PC 웹 서비스에 집중합니다. 모바일 앱, 통화 중 실시간 분석, 자동 녹음 연동은 MVP 범위에 포함하지 않습니다.

## 4. 제품 목표

| 우선순위 | 목표 | 설명 |
|---|---|---|
| 1 | 위험 인지 지원 | 통화 단위의 정상·보이스피싱 의심 결과를 제공합니다. |
| 2 | 확인 구간 제공 | 보이스피싱 의심 결과일 때 높은 점수의 대화 구간을 최대 3개 제공합니다. |
| 3 | 개인정보 보호 | 음성·전사·분석 결과를 영구 저장하지 않습니다. |
| 4 | 모델 검증 | 전처리부터 최종 결과까지의 E2E 파이프라인을 검증합니다. |

## 5. MVP 범위

### 5.1 포함 범위

- 한국어 음성파일 업로드
- `.wav`, `.mp3`, `.m4a` 입력 지원
- 업로드 전 개인정보 처리 안내 및 동의 확인
- 음성파일 실제 형식·손상 여부·음성 스트림 검증
- Faster-Whisper 입력 기준인 `mono / 16kHz / 16-bit signed PCM` 전처리
- Faster-Whisper CTranslate2 경량 모델 기반 STT
- Faster-Whisper 언어 감지를 통한 한국어 여부 확인
- 전사 결과의 메모리 기반 처리
- 음성 파일 청킹 및 청크 간 오버랩 처리
- Dialog-KoELECTRA-Small ONNX 경량 모델 기반 이진분류
- 청크 점수의 통화 단위 집계
- Validation 기반 threshold 결정
- 최종 정상 통화·보이스피싱 의심 라벨 표시
- 보이스피싱 점수 기반 최종 의심도 퍼센트 표시
- 보이스피싱 의심 결과일 때 상위 3개 대화 구간 표시
- 비동기 분석 작업 생성 및 단계별 진행 상태 표시
- 분석 작업 취소 및 취소 시 결과 폐기
- 분석 중 전체 작업을 취소하는 취소 버튼
- FastAPI 메모리 기반 사용자별 중복 분석 잠금 및 IP 요청 제한
- 분석 완료·실패·취소 후 원본·임시 데이터 삭제
- Streamlit 테스트 환경
- Railway FastAPI E2E 테스트

### 5.2 제외 범위

- 모바일 앱
- 통화 중 실시간 분석
- 스마트폰 자동 녹음 연동
- 녹음파일 자동 로딩
- 화자 분리 및 화자 식별
- CSV 기반 전사 저장
- 회원가입·로그인
- 분석 이력 저장
- 결과 파일 다운로드
- 음성 재생 기능
- 전화번호 자동 차단
- 자동 신고·보호자 연락
- 딥페이크·딥보이스 판별
- TTS 및 음성 경고
- 법적·수사적 확정 판정

### 5.3 Post-MVP

- 모바일 앱

## 6. 사용자 흐름

### 6.1 최초 진입

1. 사용자가 웹페이지에 접속합니다.
2. 개인정보 처리 안내와 동의 화면을 표시합니다.
3. 사용자가 동의하면 모델 상태 확인을 시작합니다.
4. 모델이 준비될 때까지 `모델 준비 중` 화면을 표시합니다.
5. Faster-Whisper와 Dialog-KoELECTRA 모델이 모두 준비되면 파일 업로드를 활성화합니다.
6. 동의 여부는 서버나 데이터베이스에 저장하지 않습니다.
7. 페이지를 새로 열면 다시 동의를 받습니다.

### 6.2 분석 흐름

1. 사용자가 `.wav`, `.mp3`, `.m4a` 중 하나를 선택합니다.
2. 시스템이 확장자와 실제 파일 형식을 확인합니다.
3. 시스템이 음성파일을 임시 처리 영역에 저장합니다.
4. `POST /analyze`가 분석 작업을 생성하고 `job_id`를 반환합니다.
5. 프론트엔드가 `GET /analyze/{job_id}`를 주기적으로 호출하여 작업 상태와 단계별 진행 상황을 표시합니다.
6. 오디오를 `mono / 16kHz / 16-bit signed PCM`으로 디코딩·리샘플링합니다. 원본이 MP3·M4A인 경우에도 반드시 WAV 파일로 저장하지 않고 Faster-Whisper 입력으로 직접 전달할 수 있습니다.
7. 긴 음성 파일을 학습·검증 설정에 맞는 청크로 나누고, 필요한 경우 청크 간 오버랩을 적용합니다.
8. Faster-Whisper가 각 음성 청크의 언어를 감지합니다.
9. 한국어가 아니면 분석을 중단하고 안내합니다.
10. 각 음성 청크를 전사하고 청크별 문장·시간 정보를 메모리에 보관합니다.
11. 전사 텍스트를 정규화한 뒤 각 음성 청크 단위로 보이스피싱 점수를 산출합니다.
12. Validation에서 정한 집계 방식으로 통화 단위 점수를 계산합니다.
13. 보이스피싱 의심 결과이면 점수가 높은 구간을 정렬하고 겹치는 구간을 통합합니다.
14. 분석 완료 시 결과를 상태 조회 응답에 포함하고 화면에 표시합니다.
15. 사용자가 취소 버튼을 누르면 전체 분석 작업을 취소하고 현재까지의 결과를 폐기합니다.
16. 성공·실패·취소 여부와 관계없이 음성파일과 임시 데이터를 삭제합니다.

사용자가 분석 중 취소 버튼을 누르면 프론트엔드는 `DELETE /analyze/{job_id}`를 호출합니다. 서버는 전체 작업을 취소 상태로 변경하고 현재 단계에서 가능한 가장 빠른 시점에 전처리·전사·분류·집계 작업을 중단합니다. 이미 진행 중인 연산의 즉시 중단은 보장하지 않으며, 취소된 작업의 결과는 화면에 표시하지 않습니다.

### 6.3 사용자 결과

항상 표시:

- `정상 통화` 또는 `보이스피싱 의심`
- 보이스피싱 점수 기반 의심도 퍼센트(소수 첫째 자리)
- 간단한 안내 문구

보이스피싱 의심일 때만 표시:

- 점수가 높은 최대 3개 대화 구간
- 구간 시작·종료 시간(`분:초`)
- 정해진 길이로 제한한 대화 텍스트

상위 구간에는 화자 ID, 구간별 점수, 음성 재생 기능을 표시하지 않습니다. 표시 글자 수와 안내 문구는 추후 팀에서 결정합니다.

## 7. 성공 기준

- 지원 형식 파일이 업로드부터 결과 표시까지 처리됩니다.
- 비한국어·손상·지원하지 않는 파일을 적절히 차단합니다.
- 음성 청킹·STT·분류·통화 단위 집계가 E2E로 실행됩니다.
- Recall, FNR, FPR, Precision, F1을 Main Test Set에서 측정합니다.
- Hard Negative Test와 Low-quality Test를 별도로 평가합니다.
- 원본 음성·전사·중간 산출물이 서비스 처리 후 남지 않습니다.
- Railway 환경에서 경량 모델 실행 가능성을 실제로 검증합니다.
- Railway에서 실행이 어려우면 공통 분석 모듈과 API 계약을 유지한 채 다른 FastAPI 호스팅 환경으로 전환할 수 있습니다.

실제로 측정하지 않은 성능 수치를 PRD·README에 작성하지 않습니다. 10분 통화 처리 속도는 측정·개선 대상이며, MVP의 고정 합격 시간으로 설정하지 않습니다.

# Part 2. SDD

## 8. 시스템 아키텍처

### 8.1 1차 배포 구조

```text
사용자 PC 브라우저
        ↓ HTTPS
Netlify Nuxt.js 프론트엔드
        ↓ API 호출
Railway FastAPI 백엔드
 ├─ FastAPI API
 ├─ Faster-Whisper CTranslate2 INT8
 ├─ Dialog-KoELECTRA ONNX INT8
 └─ 공통 분석 모듈
        ↓ 서버 상태 관리
FastAPI 메모리
 ├─ 작업 상태·결과 임시 관리
 ├─ 사용자별 분석 잠금
 └─ IP 요청 제한
```

Railway는 1차 백엔드 실행 환경입니다. CPU·메모리·실행 시간 또는 배포 운영 조건으로 안정적인 실행이 어렵거나 경량 모델의 성능이 허용하기 어려운 수준으로 저하되면 다음 구조를 검토합니다.

```text
Netlify Nuxt.js 프론트엔드
        ↓ HTTPS
다른 호스팅 환경의 FastAPI 서버
 ├─ 공통 분석 모듈
 └─ 경량 또는 원본 모델
```

다른 호스팅 환경으로 전환하더라도 프론트엔드 API 계약과 공통 분석 모듈 인터페이스를 유지합니다.

### 8.2 테스트 구조

```text
Streamlit 테스트 화면
        ↓
공통 분석 모듈
        ↓
동일한 전처리·음성 청킹·STT·분류·집계
```

Streamlit은 모델과 파이프라인을 검증하는 테스트 환경이며 최종 사용자 서비스 화면으로 사용하지 않습니다. 최종 사용자 화면은 Nuxt.js로 구현합니다.

## 9. 공통 분석 모듈

분석 로직은 화면·API와 분리합니다.

```text
audio preprocessing
    → speech transcription
    → text chunking
    → chunk classification
    → call aggregation
    → reference segment selection
    → result formatting
    → temporary data cleanup
```

권장 모듈 책임:

| 모듈 | 책임 |
|---|---|
| 오디오 전처리 | 확장자·손상·음성 스트림 확인, mono / 16kHz / 16-bit signed PCM 입력으로 디코딩·리샘플링 |
| STT | 언어 감지, 한국어 검증, 시간 정보가 있는 전사 |
| 음성 청킹 | 긴 음성 분할 및 청크 간 오버랩 처리 |
| 텍스트 처리 | 음성 청크별 전사 결과 정규화 |
| 분류 | 음성 청크별 전사 텍스트의 보이스피싱 점수 산출 |
| 집계 | 음성 청크 점수를 통화 단위 점수로 변환 |
| 구간 선택 | 고득점 구간 정렬·중복 통합·최대 3개 추출 |
| 결과 포맷 | API·Nuxt.js·Streamlit이 공유하는 결과 구조 생성 |
| 정리 | 임시 음성·전사·중간 데이터 삭제 |

화자 분리는 사용하지 않습니다. 따라서 전사 결과에는 화자 필드를 두지 않고 시간 정보와 텍스트만 유지합니다. 전사 결과를 CSV로 저장하지 않고 메모리에서 다음 단계로 전달합니다.

## 10. 모델 설계

### 10.1 STT

- 후보·기준: Faster-Whisper CTranslate2 경량 모델
- 실행: CPU `int8` 우선
- 저장: Hugging Face Hub 모델 저장소 후보
- 초기화: 분류 모델과 병렬 로드
- 준비 완료 기준: STT·분류 모델이 모두 로드됨
- 언어: 한국어만 지원

Faster-Whisper의 언어 감지 결과가 한국어가 아니면 분석을 중단합니다. 별도의 언어 분류 모델은 추가하지 않습니다.

### 10.2 분류

- 기반 모델: Dialog-KoELECTRA-Small
- 배포 형식: ONNX INT8 우선
- 실행 엔진: ONNX Runtime CPU
- 출력: 보이스피싱 클래스 점수
- 사용자 표시: 점수 × 100을 소수 첫째 자리 퍼센트로 표시

### 10.3 경량 모델 선택 기준

원본 모델과 경량 모델을 동일한 Validation·Test Set에서 비교합니다.

평가 우선순위:

1. Recall
2. FNR
3. FPR
4. Precision·F1
5. 처리 시간·메모리 사용량

경량 모델의 성능이 허용하기 어려운 수준으로 저하되면 Railway 실행 가능성보다 성능을 우선하고 다른 FastAPI 호스팅 환경을 검토합니다. Railway에서 실행이 불가능한 경우에는 다른 서버로 전환하며, 경량 모델 성능이 부족할 때만 원본 모델을 검토합니다.

모델 저장소의 공개·비공개 여부는 미정입니다. 비공개 저장소를 사용하는 경우 Hugging Face 접근 토큰은 Railway 환경변수에만 보관하고 프론트엔드에 노출하지 않습니다.

## 11. 입력 및 전처리

| 항목 | 기준 |
|---|---|
| 지원 확장자 | `.wav`, `.mp3`, `.m4a` |
| 지원 언어 | 한국어 |
| Faster-Whisper 전사 입력 형식 | mono / 16kHz / 16-bit signed PCM (WAV 저장은 선택 사항) |
| 최대 음성 길이 | 초기 제한 없음, 성능 측정 후 결정 가능 |
| 최대 파일 크기 | 초기 제한 없음, 플랫폼·성능 측정 후 결정 가능 |
| 동시 업로드 | 사용자 화면에서 한 번에 한 파일 |

업로드 파일은 `POST /analyze` 요청으로 직접 전달합니다. 외부 파일 저장소에 저장하지 않고 분석 중 임시 메모리·임시 파일로만 사용합니다.

## 12. 음성 청킹 및 점수 집계

### 12.1 청킹

- 음성 파일을 Faster-Whisper가 처리할 수 있는 길이의 청크로 분할
- 기본 청크 길이와 오버랩은 STT 파인튜닝 학습·검증 설정을 우선 적용
- 문장 경계 손실을 줄이기 위해 필요한 경우 청크 간 오버랩 적용
- 오버랩으로 발생한 중복 전사는 시간 정보와 중복 구간을 기준으로 병합
- 최종 청크 길이와 오버랩은 Validation 결과에 따라 조정 가능
- 최종 Test 평가 전 설정 고정
- 음성 청크와 전사 결과의 시간 범위는 다음 단계까지 유지

### 12.2 통화 단위 집계

다음 후보를 Validation Set에서 비교합니다.

- 최대 청크 점수
- 전체 청크 평균
- 상위 청크 평균
- 상위 일정 비율 청크 평균

Recall과 FNR을 우선하고 FPR을 함께 검토하여 최종 집계 방식을 선택합니다. Test Set에서는 선택한 방식을 고정합니다.

### 12.3 Threshold

- Validation Set에서 threshold 후보 비교
- Recall·FNR 우선, FPR·Precision·F1 함께 확인
- 최종 threshold 선택 후 Test 평가 전에 고정
- Test 결과를 보고 threshold를 다시 조정하지 않음

### 12.4 상위 참고 구간

- 보이스피싱 의심 결과일 때만 추출
- 청크별 보이스피싱 점수가 높은 순으로 정렬
- 겹치거나 거의 같은 구간은 통합
- 통합 후 최대 3개 표시
- 구간 점수는 내부 선정에만 사용하고 사용자 화면에는 표시하지 않음
- 화면에는 시작·종료 시간과 제한된 길이의 텍스트만 표시
- 텍스트 표시 길이는 미정

## 13. API 설계

### 13.1 엔드포인트

| Method | Path | 역할 |
|---|---|---|
| GET | `/health` | API 서버 상태 확인 |
| GET | `/model-status` | 두 모델의 준비 상태 확인 |
| POST | `/analyze` | 음성파일 분석 작업 생성 및 `job_id` 반환 |
| GET | `/analyze/{job_id}/status` | 분석 작업 상태 조회 |
| GET | `/analyze/{job_id}/result` | 분석 작업 완료 조회 |
| DELETE | `/analyze/{job_id}` | 분석 작업 취소 및 결과 폐기 |

분석은 비동기 작업으로 처리합니다. 프론트엔드는 상태 조회 API를 주기적으로 호출하여 사용자에게 현재 분석 단계를 표시합니다. 별도의 결과 다운로드 API는 사용하지 않습니다.

MVP에서는 FastAPI 백엔드의 작업 실행 모듈과 메모리 기반 작업 레지스트리를 사용합니다. 작업 상태와 결과는 작업이 진행되는 동안 해당 백엔드 인스턴스의 메모리에만 보관하며, 음성·전사·최종 결과를 데이터베이스나 외부 파일 저장소에 저장하지 않습니다. 따라서 서버 재시작이나 작업 프로세스 장애가 발생하면 해당 작업은 실패 처리하고 임시 데이터를 정리합니다. 다중 인스턴스 실행이나 분석 이력 저장이 필요해지는 경우 데이터베이스 도입을 별도로 검토합니다.

### 13.2 `/health`

API 서버가 응답 가능한지만 확인합니다. 모델 로드를 수행하지 않습니다.

```json
{
  "status": "ok",
  "service": "voice-analysis-api",
  "version": "0.1.0",
  "timestamp": "2026-08-16T12:00:00Z"
}
```

### 13.3 `/model-status`

두 모델을 병렬로 로드하고 상태를 확인합니다.

내부 상태:

- `loading`: 하나 이상의 모델 로딩 중
- `ready`: 두 모델 모두 사용 가능
- `error`: 하나 이상의 모델 로딩 실패

사용자 화면에는 `모델 준비 중`, `모델 준비 완료`, `모델 준비 실패`로 표시합니다. 프론트엔드는 주기적으로 상태를 확인하고 `ready`일 때 업로드를 활성화합니다.

### 13.4 `/analyze`

```text
Method: POST
Content-Type: multipart/form-data
Field: audio
```

작업 생성 응답:

```json
{
  "job_id": "job_12345",
  "status": "queued",
  "stage": "queued"
}
```

작업 생성 응답 규칙:

- `job_id`: 상태 조회와 취소에 사용하는 작업 식별자
- `status`: `queued`, `running`, `completed`, `failed`, `cancelled`
- `stage`: 사용자 화면에 표시할 현재 처리 단계

### 13.5 `GET /analyze/{job_id}`

프론트엔드는 일정한 주기로 작업 상태를 조회합니다. MVP에서는 정확한 숫자 퍼센트를 제공하지 않고 다음 단계 중 하나를 표시합니다.

- `queued`: 분석 대기 중
- `preprocessing`: 음성 파일 확인 및 전처리 중
- `chunking`: 음성 파일을 분석 청크로 분할하고 오버랩을 적용하는 중
- `transcribing`: 한국어 음성 전사 중
- `classifying`: 청크 분류 및 점수 계산 중
- `finalizing`: 통화 단위 결과와 상위 구간 정리 중
- `completed`: 분석 완료
- `failed`: 분석 실패
- `cancelled`: 분석 취소

완료 응답:

```json
{
  "job_id": "job_12345",
  "status": "completed",
  "stage": "completed",
  "result": {
    "label": "보이스피싱 의심",
    "score": 87.4,
    "segments": [
      {
        "start_time": "02:00",
        "end_time": "02:14",
        "text": "확인이 필요한 대화 내용"
      }
    ],
    "advice": ""
  }
}
```

결과 규칙:

- `label`: `정상 통화` 또는 `보이스피싱 의심`
- `score`: 보이스피싱 점수 기반 의심도, 소수 첫째 자리
- `segments`: 정상 통화이면 `[]`, 의심 결과이면 최대 3개
- `advice`: 항상 반환하며 문구 확정 전에는 빈 문자열 허용
- `job_id`: 로그 추적용, 음성·개인정보를 포함하지 않음

`failed` 또는 `cancelled` 상태에서는 `result`를 반환하지 않습니다. 상태 조회가 완료되면 프론트엔드는 결과를 화면에 표시하고 추가 상태 조회를 중단합니다.

### 13.6 `DELETE /analyze/{job_id}`

분석 취소 요청은 작업 상태를 `cancelled`로 변경하고 결과를 폐기하는 방식으로 처리합니다.

- 사용자가 취소하면 현재까지 생성된 결과 폐기
- 음성파일·임시 전사·중간 결과 삭제
- 서버는 처리 단계 완료 시 취소·연결 종료 여부 확인
- 확인 가능한 가장 빠른 시점에 모델 추론 중단
- 이미 진행 중인 연산의 즉시 중단은 보장하지 않음
- 이미 완료된 작업의 취소 요청은 취소할 수 없으며 완료 결과를 유지

## 14. 오류 처리

오류 응답은 다음 공통 구조를 사용합니다.

```json
{
  "request_id": "req_12345",
  "error_code": "AUDIO.CONVERSION_FAILED",
  "stage": "audio_preprocessing",
  "message": "음성 파일을 처리할 수 없습니다.",
  "retryable": true
}
```

대표 오류 단계:

```text
REQUEST.*
AUDIO.*
MODEL.*
STT.*
TEXT.*
CLASSIFICATION.*
RESULT.*
SERVER.*
```

사용자 화면에는 전문 오류코드나 스택 트레이스를 표시하지 않습니다. 오류 발생 시 재시도 가능 여부에 따라 재시도 버튼을 표시하고, 실패한 음성·임시 데이터를 삭제합니다.

## 15. 데이터베이스 및 상태 관리

현재 MVP에서는 별도의 데이터베이스를 사용하지 않습니다. FastAPI 메모리에서 사용자별 중복 분석 잠금, IP 요청 제한, 분석 작업 상태·결과를 작업 실행 중에만 임시로 관리합니다.

- 원본 음성·전사 원문·청크 텍스트·모델 점수·최종 결과·사용자 이력을 데이터베이스에 저장하지 않음
- 성공·실패·취소 후 임시 상태와 분석 데이터를 삭제
- 서버 재시작 시 진행 중 작업은 실패 처리
- 서버를 여러 인스턴스로 운영하거나 사용자별 분석 이력·장기 보관이 필요해질 경우 데이터베이스 도입 검토
- 데이터베이스 도입 시 Supabase를 후보로 검토할 수 있으나 현재 구현·배포 계획에는 포함하지 않음

### 15.1 사용자별 중복 분석 잠금

- 분석 시작 전에 사용자를 식별할 수 있는 키로 FastAPI 메모리에서 잠금 상태를 확인
- 동일 사용자의 분석 작업이 진행 중이면 새 분석 요청을 거절
- 다른 사용자의 분석 요청은 허용
- 분석 성공·실패·취소 후 해당 사용자의 잠금 해제
- 비정상 종료에 대비해 잠금 만료 시간 설정
- 만료된 잠금은 다음 요청에서 정리

현재 MVP에는 회원가입·로그인이 없으므로 사용자 식별 키는 서버에서 생성한 IP 해시를 사용합니다. 이후 인증이나 세션 기능을 도입하면 IP 해시 대신 사용자 ID 또는 세션 ID 기반 잠금으로 전환할 수 있습니다.

### 15.2 IP 요청 제한

- IP 원문 대신 해시값을 사용
- 일정 시간 창 내 분석 요청 횟수 제한
- 제한 초과 시 `SERVICE.RATE_LIMITED` 반환
- 요청 제한 데이터에 만료 시간 적용
- 잠금과 요청 제한 상태는 FastAPI 백엔드 메모리에서만 관리

## 16. 개인정보 및 보안

- 페이지 최초 진입 시 개인정보 처리 안내와 동의 표시
- 동의 전 파일 업로드·분석 비활성화
- 페이지를 새로 열면 다시 동의 확인
- 음성파일은 분석 요청 중에만 임시 처리
- 분석 완료·실패·취소 후 음성·전사·중간 산출물 삭제

- 실제 녹음파일은 명시적 동의를 받은 파일만 E2E 테스트에 사용
- 별도 동의서 파일은 보관하지 않음
- 테스트 로컬 환경에서는 오류 분석을 위한 일시적 보관 허용
- Railway 환경에서는 처리 후 즉시 삭제
- GitHub·Hugging Face 또는 향후 도입되는 외부 저장소에 실제 녹음파일 업로드 금지

1. 공통 분석 모듈 단위 테스트

- 실제 녹음파일의 개인식별정보는 가능한 범위에서 비식별화

### 17.3 모델 평가

| 대상 | 지표 |
|---|---|
| STT | CER, WER, 처리 시간, 메모리 |
| 분류 | Recall, FNR, FPR, Precision, F1 |
| 강건성 | Hard Negative·Low-quality 별도 성능 |
| 배포 | 모델 다운로드 시간, 초기화 시간, 실행 시간, 메모리 |
| E2E | 업로드·검증·분석·결과·삭제 흐름 |

경량화 모델이 원본보다 성능이 낮을 경우 Recall·FNR을 우선하여 최종 모델을 선택합니다. Railway 실행 가능성보다 성능을 우선해야 한다고 판단되면 다른 FastAPI 호스팅 환경으로 전환합니다.
