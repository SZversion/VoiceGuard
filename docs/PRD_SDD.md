# Part 1. PRD

## 1. 제품 개요

보이스피싱 통화 녹음파일을 업로드하면 한국어 음성 전사와 텍스트 분류를 수행하여 통화가 정상인지 보이스피싱으로 의심되는지 안내하는 서비스입니다.

사용자는 최종 이진 분류 결과와 보이스피싱 의심도, 의심 결과일 때 모델 점수가 높은 대화 구간을 확인할 수 있습니다. 이 서비스는 법적·수사적 확정 판정이 아닌 참고 정보를 제공합니다.

### One-Line Definition

통화 녹음파일을 분석하여 보이스피싱 의심 여부와 확인이 필요한 대화 구간을 제공하는 PC용 음성 분석 서비스입니다.

## 2. 문제 정의

보이스피싱은 기관 사칭, 긴급성, 비밀 유지 요구, 개인정보·송금 요구를 정상적인 절차처럼 구성합니다. 사용자는 통화 당시 위험을 인지하지 못하거나 통화 종료 후에도 피해 상황을 판단하기 어려울 수 있습니다.

정상 금융 상담에도 계좌, 대출, 이체, 본인 확인 등의 표현이 사용되므로 특정 단어만으로 판단할 수 없습니다. 전체 통화의 문맥을 전사하고 분류하여 사용자가 다시 확인할 구간을 제공해야 합니다.

## 3. 목표 사용자

- 보이스피싱 통화를 정상적인 금융·수사 절차로 오인하기 쉬운 사용자
- 통화 후 녹음파일을 확인하고 싶은 PC 사용자
- 정상 금융 상담과 의심 통화를 구분하기 어려운 사용자

MVP는 PC 웹 서비스에 집중합니다. 모바일 앱, 통화 중 실시간 분석, 자동 녹음 연동은 MVP 범위에 포함하지 않습니다.

## 4. 제품 목표

| 우선순위 | 목표 | 설명 |
|---|---|---|
| 1 | 위험 인지 지원 | 통화 단위의 정상·보이스피싱 의심 결과를 제공합니다. |
| 2 | 확인 구간 제공 | 보이스피싱 의심 결과일 때 높은 점수의 대화 구간을 최대 3개 제공합니다. |
| 3 | 개인정보 보호 | 음성·전사·분석 결과를 영구 저장하지 않습니다. |
| 4 | 모델 검증 | 전처리부터 최종 결과까지의 E2E 파이프라인을 검증합니다. |

## 5. MVP 범위

### 5.1 포함 범위

- 한국어 음성파일 업로드
- `.wav`, `.mp3`, `.m4a` 입력 지원
- 업로드 전 개인정보 처리 안내 및 동의 확인
- 음성파일 실제 형식·손상 여부·음성 스트림 검증
- `mono / 8kHz / 16-bit PCM WAV` 변환
- Faster-Whisper CTranslate2 경량 모델 기반 STT
- Faster-Whisper 언어 감지를 통한 한국어 여부 확인
- 전사 결과의 메모리 기반 처리
- 텍스트 청킹
- Dialog-KoELECTRA-Small ONNX 경량 모델 기반 이진분류
- 청크 점수의 통화 단위 집계
- Validation 기반 threshold 결정
- 최종 정상 통화·보이스피싱 의심 라벨 표시
- 보이스피싱 점수 기반 최종 의심도 퍼센트 표시
- 보이스피싱 의심 결과일 때 상위 3개 대화 구간 표시
- Supabase 기반 전역 분석 잠금 및 IP 요청 제한
- 분석 완료·실패·취소 후 원본·임시 데이터 삭제
- Streamlit 테스트 환경
- Vercel E2E 테스트

### 5.2 제외 범위

- 모바일 앱
- 통화 중 실시간 분석
- 스마트폰 자동 녹음 연동
- 녹음파일 자동 로딩
- 화자 분리 및 화자 식별
- CSV 기반 전사 저장
- 회원가입·로그인
- 분석 이력 저장
- 결과 파일 다운로드
- 음성 재생 기능
- 전화번호 자동 차단
- 자동 신고·보호자 연락
- 딥페이크·딥보이스 판별
- TTS 및 음성 경고
- 법적·수사적 확정 판정

### 5.3 Post-MVP

- 모바일 앱
- 자동 녹음파일 로딩
- 통화 종료 후 자동 분석
- 고령자용 접근성 개선
- 온디바이스 실행 방식 검토
- 사용자 계정과 분석 이력

## 6. 사용자 흐름

### 6.1 최초 진입

1. 사용자가 웹페이지에 접속합니다.
2. 개인정보 처리 안내와 동의 화면을 표시합니다.
3. 사용자가 동의하면 모델 상태 확인을 시작합니다.
4. 모델이 준비될 때까지 `모델 준비 중` 화면을 표시합니다.
5. Faster-Whisper와 Dialog-KoELECTRA 모델이 모두 준비되면 파일 업로드를 활성화합니다.
6. 동의 여부는 서버나 Supabase에 저장하지 않습니다.
7. 페이지를 새로 열면 다시 동의를 받습니다.

### 6.2 분석 흐름

1. 사용자가 `.wav`, `.mp3`, `.m4a` 중 하나를 선택합니다.
2. 시스템이 확장자와 실제 파일 형식을 확인합니다.
3. 시스템이 음성파일을 임시 처리 영역에 저장합니다.
4. `POST /analyze`가 동기 방식으로 분석을 수행합니다.
5. 오디오를 표준 WAV로 변환합니다.
6. Faster-Whisper가 언어를 감지합니다.
7. 한국어가 아니면 분석을 중단하고 안내합니다.
8. 한국어 음성을 전사하고 문장·시간 정보를 메모리에 보관합니다.
9. 전사 텍스트를 청크로 분할합니다.
10. 청크별 보이스피싱 점수를 산출합니다.
11. Validation에서 정한 집계 방식으로 통화 단위 점수를 계산합니다.
12. 보이스피싱 의심 결과이면 점수가 높은 구간을 정렬하고 겹치는 구간을 통합합니다.
13. 최종 결과를 화면에 표시합니다.
14. 성공·실패·취소 여부와 관계없이 음성파일과 임시 데이터를 삭제합니다.

### 6.3 사용자 결과

항상 표시:

- `정상 통화` 또는 `보이스피싱 의심`
- 보이스피싱 점수 기반 의심도 퍼센트(소수 첫째 자리)
- 간단한 안내 문구

보이스피싱 의심일 때만 표시:

- 점수가 높은 최대 3개 대화 구간
- 구간 시작·종료 시간(`분:초`)
- 정해진 길이로 제한한 대화 텍스트

상위 구간에는 화자 ID, 구간별 점수, 음성 재생 기능을 표시하지 않습니다. 표시 글자 수와 안내 문구는 추후 팀에서 결정합니다.

## 7. 성공 기준

- 지원 형식 파일이 업로드부터 결과 표시까지 처리됩니다.
- 비한국어·손상·지원하지 않는 파일을 적절히 차단합니다.
- STT·청킹·분류·통화 단위 집계가 E2E로 실행됩니다.
- Recall, FNR, FPR, Precision, F1을 Main Test Set에서 측정합니다.
- Hard Negative Test와 Low-quality Test를 별도로 평가합니다.
- 원본 음성·전사·중간 산출물이 서비스 처리 후 남지 않습니다.
- Vercel 환경에서 경량 모델 실행 가능성을 실제로 검증합니다.
- Vercel에서 실행이 어려우면 공통 분석 모듈을 유지한 채 별도 FastAPI 서버로 전환할 수 있습니다.

실제로 측정하지 않은 성능 수치를 PRD·README에 작성하지 않습니다. 10분 통화 처리 속도는 측정·개선 대상이며, MVP의 고정 합격 시간으로 설정하지 않습니다.

# Part 2. SDD

## 8. 시스템 아키텍처

### 8.1 1차 배포 구조

```text
사용자 PC 브라우저
        ↓ HTTPS
Vercel 프론트엔드(기술 미정)
        ↓ API 호출
Vercel Python Function
 ├─ FastAPI API
 ├─ Faster-Whisper CTranslate2 INT8
 ├─ Dialog-KoELECTRA ONNX INT8
 └─ 공통 분석 모듈
        ↓ 서버 상태 관리
Supabase
 ├─ 전역 분석 잠금
 └─ IP 요청 제한
```

Vercel은 1차 실행 환경입니다. CPU·메모리·실행 시간 제한으로 안정적인 실행이 어렵거나 경량 모델의 성능이 허용하기 어려운 수준으로 저하되면 다음 구조로 전환합니다.

```text
Vercel 프론트엔드
        ↓ HTTPS
별도 FastAPI 서버
 ├─ 공통 분석 모듈
 └─ 경량 또는 원본 모델
```

별도 FastAPI 서버로 전환하더라도 프론트엔드 API 계약과 공통 분석 모듈 인터페이스를 유지합니다.

### 8.2 테스트 구조

```text
Streamlit 테스트 화면
        ↓
공통 분석 모듈
        ↓
동일한 전처리·STT·청킹·분류·집계
```

Streamlit은 모델과 파이프라인을 검증하는 테스트 환경이며 최종 사용자 서비스 화면으로 고정하지 않습니다.

## 9. 공통 분석 모듈

분석 로직은 화면·API와 분리합니다.

```text
audio preprocessing
    → speech transcription
    → text chunking
    → chunk classification
    → call aggregation
    → reference segment selection
    → result formatting
    → temporary data cleanup
```

권장 모듈 책임:

| 모듈 | 책임 |
|---|---|
| 오디오 전처리 | 확장자·손상·음성 스트림 확인, 표준 WAV 변환 |
| STT | 언어 감지, 한국어 검증, 시간 정보가 있는 전사 |
| 텍스트 처리 | 정규화 및 청크 분할 |
| 분류 | 청크별 보이스피싱 점수 산출 |
| 집계 | 청크 점수를 통화 단위 점수로 변환 |
| 구간 선택 | 고득점 구간 정렬·중복 통합·최대 3개 추출 |
| 결과 포맷 | API·Streamlit이 공유하는 결과 구조 생성 |
| 정리 | 임시 음성·전사·중간 데이터 삭제 |

화자 분리는 사용하지 않습니다. 따라서 전사 결과에는 화자 필드를 두지 않고 시간 정보와 텍스트만 유지합니다. 전사 결과를 CSV로 저장하지 않고 메모리에서 다음 단계로 전달합니다.

## 10. 모델 설계

### 10.1 STT

- 후보·기준: Faster-Whisper CTranslate2 경량 모델
- 실행: CPU `int8` 우선
- 저장: Hugging Face Hub 모델 저장소 후보
- 초기화: 분류 모델과 병렬 로드
- 준비 완료 기준: STT·분류 모델이 모두 로드됨
- 언어: 한국어만 지원

Faster-Whisper의 언어 감지 결과가 한국어가 아니면 분석을 중단합니다. 별도의 언어 분류 모델은 추가하지 않습니다.

### 10.2 분류

- 기반 모델: Dialog-KoELECTRA-Small
- 배포 형식: ONNX INT8 우선
- 실행 엔진: ONNX Runtime CPU
- 출력: 보이스피싱 클래스 점수
- 사용자 표시: 점수 × 100을 소수 첫째 자리 퍼센트로 표시

### 10.3 경량 모델 선택 기준

원본 모델과 경량 모델을 동일한 Validation·Test Set에서 비교합니다.

평가 우선순위:

1. Recall
2. FNR
3. FPR
4. Precision·F1
5. 처리 시간·메모리 사용량

경량 모델의 성능이 허용하기 어려운 수준으로 저하되면 Vercel 실행 가능성보다 성능을 우선하고 별도 FastAPI 서버 배포를 검토합니다. Vercel에서 실행이 불가능한 경우에는 별도 서버로 전환하며, 경량 모델 성능이 부족할 때만 원본 모델을 검토합니다.

모델 저장소의 공개·비공개 여부는 미정입니다. 비공개 저장소를 사용하는 경우 Hugging Face 접근 토큰은 Vercel 환경변수에만 보관하고 프론트엔드에 노출하지 않습니다.

## 11. 입력 및 전처리

| 항목 | 기준 |
|---|---|
| 지원 확장자 | `.wav`, `.mp3`, `.m4a` |
| 지원 언어 | 한국어 |
| 내부 오디오 형식 | mono / 8kHz / 16-bit PCM WAV |
| 최대 음성 길이 | 초기 제한 없음, 성능 측정 후 결정 가능 |
| 최대 파일 크기 | 초기 제한 없음, 플랫폼·성능 측정 후 결정 가능 |
| 동시 업로드 | 사용자 화면에서 한 번에 한 파일 |

업로드 파일은 `POST /analyze` 요청으로 직접 전달합니다. Vercel Blob에 저장하지 않고 분석 중 임시 메모리·임시 파일로만 사용합니다.

## 12. 텍스트 처리 및 점수 집계

### 12.1 청킹

- 초기 청크 크기: 256토큰
- 초기 overlap: 64토큰
- Validation 결과에 따라 조정 가능
- 최종 Test 평가 전 설정 고정
- 전사 내부 자료구조는 구현 단계에서 결정

### 12.2 통화 단위 집계

다음 후보를 Validation Set에서 비교합니다.

- 최대 청크 점수
- 전체 청크 평균
- 상위 청크 평균
- 상위 일정 비율 청크 평균

Recall과 FNR을 우선하고 FPR을 함께 검토하여 최종 집계 방식을 선택합니다. Test Set에서는 선택한 방식을 고정합니다.

### 12.3 Threshold

- Validation Set에서 threshold 후보 비교
- Recall·FNR 우선, FPR·Precision·F1 함께 확인
- 최종 threshold 선택 후 Test 평가 전에 고정
- Test 결과를 보고 threshold를 다시 조정하지 않음

### 12.4 상위 참고 구간

- 보이스피싱 의심 결과일 때만 추출
- 청크별 보이스피싱 점수가 높은 순으로 정렬
- 겹치거나 거의 같은 구간은 통합
- 통합 후 최대 3개 표시
- 구간 점수는 내부 선정에만 사용하고 사용자 화면에는 표시하지 않음
- 화면에는 시작·종료 시간과 제한된 길이의 텍스트만 표시
- 텍스트 표시 길이는 미정

## 13. API 설계

### 13.1 엔드포인트

| Method | Path | 역할 |
|---|---|---|
| GET | `/health` | API 서버 상태 확인 |
| GET | `/model-status` | 두 모델의 준비 상태 확인 |
| POST | `/analyze` | 음성파일 동기 분석 및 결과 반환 |

비동기 작업·진행률·작업 ID·결과 다운로드 API는 MVP에서 사용하지 않습니다.

### 13.2 `/health`

API 서버가 응답 가능한지만 확인합니다. 모델 로드를 수행하지 않습니다.

```json
{
  "status": "ok",
  "service": "voice-analysis-api",
  "version": "0.1.0",
  "timestamp": "2026-08-16T12:00:00Z"
}
```

### 13.3 `/model-status`

두 모델을 병렬로 로드하고 상태를 확인합니다.

내부 상태:

- `loading`: 하나 이상의 모델 로딩 중
- `ready`: 두 모델 모두 사용 가능
- `error`: 하나 이상의 모델 로딩 실패

사용자 화면에는 `모델 준비 중`, `모델 준비 완료`, `모델 준비 실패`로 표시합니다. 프론트엔드는 주기적으로 상태를 확인하고 `ready`일 때 업로드를 활성화합니다.

### 13.4 `/analyze`

```text
Method: POST
Content-Type: multipart/form-data
Field: audio
```

성공 응답:

```json
{
  "request_id": "req_12345",
  "label": "보이스피싱 의심",
  "score": 87.4,
  "segments": [
    {
      "start_time": "02:00",
      "end_time": "02:14",
      "text": "확인이 필요한 대화 내용"
    }
  ],
  "advice": ""
}
```

응답 규칙:

- `label`: `정상 통화` 또는 `보이스피싱 의심`
- `score`: 보이스피싱 점수 기반 의심도, 소수 첫째 자리
- `segments`: 정상 통화이면 `[]`, 의심 결과이면 최대 3개
- `advice`: 항상 반환하며 문구 확정 전에는 빈 문자열 허용
- `request_id`: 로그 추적용, 음성·개인정보를 포함하지 않음

### 13.5 동기 취소

분석 취소는 브라우저의 요청 중단과 결과 폐기 방식으로 처리합니다.

- 사용자가 취소하면 현재까지 생성된 결과 폐기
- 음성파일·임시 전사·중간 결과 삭제
- 서버는 처리 단계 완료 시 취소·연결 종료 여부 확인
- 확인 가능한 가장 빠른 시점에 모델 추론 중단
- 이미 진행 중인 연산의 즉시 중단은 보장하지 않음
- 취소 전용 API·작업 큐는 사용하지 않음

## 14. 오류 처리

오류 응답은 다음 공통 구조를 사용합니다.

```json
{
  "request_id": "req_12345",
  "error_code": "AUDIO.CONVERSION_FAILED",
  "stage": "audio_preprocessing",
  "message": "음성 파일을 처리할 수 없습니다.",
  "retryable": true
}
```

대표 오류 단계:

```text
REQUEST.*
AUDIO.*
MODEL.*
STT.*
TEXT.*
CLASSIFICATION.*
RESULT.*
SERVER.*
```

사용자 화면에는 전문 오류코드나 스택 트레이스를 표시하지 않습니다. 오류 발생 시 재시도 가능 여부에 따라 재시도 버튼을 표시하고, 실패한 음성·임시 데이터를 삭제합니다.

## 15. Supabase 설계

Supabase는 모델 실행·파일 저장·사용자 계정에 사용하지 않습니다. FastAPI에서 `supabase-py`를 사용해 서버 측에서만 접근합니다.

### 15.1 저장 범위

저장하지 않는 데이터:

- 원본 음성
- 전사 원문
- 청크 텍스트
- 모델 점수
- 최종 분석 결과
- 사용자 이력

임시 관리 대상:

- 전역 분석 잠금
- IP 요청 제한 상태

### 15.2 잠금

- 분석 시작 전에 원자적으로 잠금 획득
- 잠금이 있으면 새 분석을 거절
- 성공·실패·취소 후 잠금 해제
- 비정상 종료에 대비해 만료 시간 설정
- 만료된 잠금은 다음 요청에서 정리

### 15.3 요청 제한

- IP 원문 대신 해시값 사용
- 일정 시간 창 내 요청 횟수 제한
- 초과 시 `SERVICE.RATE_LIMITED` 반환
- 제한 데이터에 만료 시간 적용

RLS와 서버 키 관리 정책을 적용하며, Supabase 비밀 키는 Vercel 환경변수에만 저장합니다.

## 16. 개인정보 및 보안

- 페이지 최초 진입 시 개인정보 처리 안내와 동의 표시
- 동의 전 파일 업로드·분석 비활성화
- 페이지를 새로 열면 다시 동의 확인
- 음성파일은 분석 요청 중에만 임시 처리
- 분석 완료·실패·취소 후 음성·전사·중간 산출물 삭제
- 로그에 음성 내용·전사문·개인정보·인증정보 기록 금지
- 실제 녹음파일은 명시적 동의를 받은 파일만 E2E 테스트에 사용
- 별도 동의서 파일은 보관하지 않음
- 테스트 로컬 환경에서는 오류 분석을 위한 일시적 보관 허용
- Vercel 환경에서는 처리 후 즉시 삭제
- GitHub·Hugging Face·Supabase에 실제 녹음파일 업로드 금지

## 17. 테스트 및 검증

### 17.1 테스트 단계

1. 공통 분석 모듈 단위 테스트
2. Streamlit에서 정상·오류·삭제 흐름 검증
3. 실제 경량화 모델을 이용한 Vercel E2E 테스트
4. Vercel 환경에서 모델 다운로드·병렬 로딩·추론·정리 검증
5. Vercel 실행이 어려울 경우 별도 FastAPI 서버에서 동일 테스트 반복

### 17.2 데이터

- 승인된 공개·학습용 테스트 데이터
- 명시적 사용 동의를 받은 실제 녹음파일
- 실제 녹음파일의 개인식별정보는 가능한 범위에서 비식별화

### 17.3 모델 평가

| 대상 | 지표 |
|---|---|
| STT | CER, WER, 처리 시간, 메모리 |
| 분류 | Recall, FNR, FPR, Precision, F1 |
| 강건성 | Hard Negative·Low-quality 별도 성능 |
| 배포 | 모델 다운로드 시간, 초기화 시간, 실행 시간, 메모리 |
| E2E | 업로드·검증·분석·결과·삭제 흐름 |

경량화 모델이 원본보다 성능이 낮을 경우 Recall·FNR을 우선하여 최종 모델을 선택합니다. Vercel 실행 가능성보다 성능을 우선해야 한다고 판단되면 별도 FastAPI 서버로 전환합니다.

## 18. 미결정 사항

- 공식 프로젝트명
- 프론트엔드 기술(React·Next.js 등)
- Hugging Face 모델 저장소 공개·비공개 여부
- 상위 구간 텍스트 표시 길이
- 최종 안내 문구
- 최종 청킹 값과 통화 단위 집계 방식
- Vercel 플랜·리전
- 모델 성능 측정 후 최대 파일 크기·음성 길이 제한

미결정 사항은 구현 전 성능·사용성·보안 검토를 통해 확정합니다. 그 외 HTTP 상태코드, 오류코드, 내부 모듈명 등 구현 세부사항은 이 문서의 원칙을 깨지 않는 범위에서 구현자가 일관되게 결정합니다.
